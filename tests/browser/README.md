# Browser acceptance

## Run

Install dependencies with `pnpm install --frozen-lockfile`, then install browsers with `pnpm exec playwright install --with-deps chrome webkit`.

```sh
pnpm check
pnpm test
pnpm build
pnpm test:ui
```

The suite starts loopback fixture servers on ports 3102 and 3103. Keep those ports free, or set `TEST_RTC_PORT` and `TEST_RELAY_PORT` to available ports. It uses independent players, synthetic cameras and microphones, and mock speech, topic, judging, and voice providers. It makes no external provider calls. The fixture and its `/__test/*` routes are never imported by the production entrypoint.

Run the departure regression repeatedly in both transports with:

```sh
pnpm exec playwright test tests/browser/recovery.spec.ts --project=rtc --project=relay -g 'Leave releases' --repeat-each=5
```

Repeat the WebKit audio and navigation regressions without retries with:

```sh
pnpm exec playwright test --project=webkit --project=webkit-relay -g 'two players.*long' --repeat-each=10 --retries=0
pnpm exec playwright test --project=webkit-relay -g 'two players complete a scored match' --repeat-each=10 --retries=0
```

CI runs type checking, core tests, and the production build on Linux, followed by six independent browser jobs on macOS 26 (Apple silicon). The browser runner uses native macOS media clocks and codecs, matching the locally validated suite and Playwright's recommendation to test WebKit media on macOS for Safari fidelity. Linux browser runs exposed missing WebKit capture progress; Intel macOS runners also showed media starvation and substantially slower rendering. These environments are not claimed as validated browser coverage. Each browser job has a 20-minute allowance and retains the JSON report, failure details, playback diagnostics, and explicit screenshots for 14 days. CI disables continuous tracing and video recording: tracing every intercepted audio packet can queue delivery for several seconds on hosted VMs. Local runs retain failure traces for debugging. The overall CI test budget is three minutes, including browser teardown; individual assertion, recovery, and playback deadlines are unchanged. Local runs retain video recording and the two-minute test budget. CI permits at most two fresh-worker retries per failed test, matching Playwright’s example CI configuration; reports retain the flaky classification and every attempt. Local runs use no retries. Persistent failures still block deployment. A local passing run does not establish that hosted CI has run successfully.

## Coverage

The `rtc`, `relay`, `phone`, `phone-relay`, `webkit`, and `webkit-relay` projects complete setup, topic selection and agreement, every speaking turn, results, recovery, and rematch through the real server-controlled game. Both clients must receive matching scores, ledgers, and results. Rematches reset points, wins, and evidence. Local video elements stay mounted across phases. Projects ending in `relay` force WebSocket media; two duplicate visual/setup scenarios are intentionally skipped there.

The pending-resume departure test deliberately changes the remaining player's microphone status after Leave. Media-health events may advance the room sequence, but the terminal outcome, participants, scores, claims, and ledger must remain unchanged. The departing client's session stays cleared and its sockets stay closed without replacements. Controlled server idempotency tests retain their exact sequence assertions.

Core tests cover the lifecycle boundaries with deterministic clocks and provider callbacks. `private-check-reconnect.test.ts` additionally uses real authenticated sockets and HTTP resume with a delayed provider stub. Recovery browser fixtures fill the current scoring budget before injecting faults so a legitimate pending judgment cannot change the baseline.

Mic requalification uses a healthy provider that can drain accepted evidence. Terminal provider failure after gameplay PCM instead aborts without granting another floor or issuing a winner, and releases its transports. Core recovery tests also hold retired streams across replacement: delayed clean finals must settle exactly once, while abnormal closure, provider error, and the original drain deadline fail safely.

`provider-runtime.test.ts` bundles the real provider factory with production ESM flags and runs it in plain Node without the test loader. Local peers deliberately keep reading while refusing WebSocket close handshakes: five terminal failures must each close within one second, an unanswered upgrade must be canceled, a silent normal drain must retain its five-second deadline, and delayed clean finals must arrive exactly once. The pinned Cartesia 4.2.0 SDK's default ESM entry selects native WebSocket without forced termination; the explicitly exported `@cartesia/cartesia-js/index.js` Node entry preserves bounded disposal. The room-accounting regression also uses uncooperative peers and requires zero active transports after each failure. These checks make no live-provider calls.

Relay admission tests schedule capture and both delivery hops independently, with opposite 60-second client wall-clock offsets, clock jumps, synchronization refreshes, and varying 0–100 ms jitter. They use the real client clock-reading path, check packet order through 600 ms delivery age, and retain the 750/751 ms boundary. The existing worklet tests establish the separate playback-buffer bound; these are deterministic admission checks, not acoustic or real-network measurements.

The long-utterance scenario renders nine seconds plus a distinct final partial frame on both clients, delays the second client’s middle packets by one second, and explicitly mutes Bonk on one client. Both worklets must report the full sample count and the server must accept both completions before normal advancement. This is render accounting with mock PCM, not a physical speaker test.

The intermittent headless WebKit RTC friend-output failure was traced to the synthetic microphone fixture acquiring and immediately discarding native audio. On the investigated macOS installation, CoreAudio reconfiguration paused both players' audio clocks despite their contexts remaining `running`. Generated capture and outbound RTP stopped advancing, with no reported packet loss; receiver concealment could fall below the existing continuity threshold. The pause also occurred without judge playback. Three diagnostic runs avoiding native microphone acquisition passed across 1,106 friend-output samples with no observed clock freezes; reintroducing acquisition reproduced the freezes and assertion failure. The fixture now acquires only the requested camera and adds its generated audio track, or creates an audio-only stream without native acquisition. Production audio paths and all continuity thresholds remain unchanged.

`synthetic-media.test.ts` guards against native audio acquisition and covers camera constraints, audio-only replacement, generator ownership, non-audio delegation, and camera errors. Baseline, acquisition-free, and reintroduction diagnostics remain under the ignored `output/playwright/webkit-investigation/` directory, including native process samples and the correlated CoreAudio log. These artifacts establish the local fixture failure mechanism, not physical-device incidence.

The initial full matrix after the microphone fixture correction exposed a separate WebKit relay reload defect: new camera Blob reads and received-frame decodes could start after `beforeunload`, when WebKit had already stopped permitting Blob access but the old document was still visible and receiving frames. The existing `pagehide`/visibility cleanup was too late. This also reproduced with the original microphone fixture. Delaying the reload response by 250 ms widened the interval and produced six Blob access-control page errors before `pagehide`; existing exception handlers did not prevent these browser-reported errors.

Production video now pauses at `beforeunload`, cancels its pending frame read, and invalidates queued or in-progress frame results using the existing generation guard. Incoming frames and delivery probes are discarded before Blob decoding while the page is inactive or hidden. A canceled navigation keeps the old document without firing `pageshow`: WebKit resumes animation frames after cancellation, so the first resumed frame reactivates video. Successful navigation cancels that callback in `pagehide`; `pageshow` clears navigation suspension. Visibility enables video only when the document is visible and navigation suspension has cleared. This preserves existing queue bounds, capture cadence, delivery checks, and protocol. `video-progress.test.ts` covers suspended encoding/decoding, pending-read cancellation, stale completion cleanup, and fresh-frame restoration. The complete-match journey checks visibility and page restoration, aborts one lobby reload and requires fresh outgoing frames/probes without device repair, then delays the existing mid-match reload response by 250 ms. Its original recovery, scoring, rematch, and empty-page-error assertions remain intact.

The navigation follow-up injects a background/foreground event pair after native `beforeunload` during the delayed reload in WebKit. With the previous guard, foreground visibility overrode navigation suspension and reproduced six Blob access-control errors (`followup-navigation-baseline-2.json`). An effect-local navigation flag now composes the two conditions; only the existing resumed animation frame or `pageshow` clears it. Chromium blocks script evaluation during intercepted navigation, so that injection is WebKit-specific; every project retains the original delayed reload and separate injected visibility and persisted page-transition checks that outgoing frames and RTC probes pause and resume. These deterministic event sequences do not establish natural-device incidence or native back/forward-cache behavior.

The decision-feedback scenario runs in all six projects. It checks lobby readiness and undo, role-specific topic selection, Enter-to-confirm feedback, subsequent Tab navigation, and a single announcement despite duplicate snapshots and clock ticks. A finished-match fixture then exercises real rematch votes during nine seconds of judge playback, with Bonk muted on one client and reduced motion on the other. Both clients must show “Rematch queued”, drain every sample, receive exactly one new-match coin event, and preserve repair/departure precedence. Peer microphone failure must keep its repair instructions visible while the healthy player’s vote stays queued. Screenshots and `decision-feedback-*.webm` recordings accompany these checks. Live-region DOM assertions establish message ownership and updates; they do not establish actual VoiceOver or other screen-reader speech.

On macOS WebKit, the decision-feedback test uses Option-Tab to include buttons in native keyboard navigation; ordinary Tab uses the browser’s default link/form-field mode. Chrome and Linux WebKit use Tab. The application does not override either navigation mode or move focus after confirmation.

The decision-feedback journey also makes another fixture room occupy the stage after both rematch votes are queued. Rejection must preserve the verdict and an actionable explanation on both clients. Once capacity is free, retry starts exactly one match and clears the obsolete notice.

## Visual checks and artifacts

The visual matrix uses schema-validated presentation snapshots for setup, coin, topics, turns, judging, results, recovery, long content, and WebGL fallback. Injected open turns also connect their matching mock transcription owner so the readiness monitor does not replace a turn screenshot with recovery during capture. Assertions run after capture as well as before it. These fixtures test rendering; they do not prove that arbitrary injected states arise during play.

Viewports include 1280×720, 1366×768, 1440×900, 1920×1080, 1024×768, 360×640, 390×844, and 844×390. Checks cover face/task/caption overlap, score pops touching task or caption content, horizontal overflow, vertical control bounds in ordinary desktop and portrait-phone states, orientation changes, keyboard focus, dialog dismissal, Device help disclosure and device selectors, permission errors, clipboard failure, and reduced motion. Long content, landscape, and zoom may scroll. Zoom coverage uses 125% CSS zoom, not native browser zoom automation. The full-caption presentation scenario runs in all six projects at desktop, 360×640, 390×844, and landscape sizes. It checks exact transcript text, unclipped wrapping, verbatim propositions and sides, central turn labels, status deduplication, optional help, keyboard focus restoration, and static reduced-motion cues. Recovery coverage checks the actual problem heading and repair action, without a generic holding message or disabled checking button.

The JSON report is written to `output/playwright/results.json`; failure traces are under `output/playwright/results/`. Screenshots and recordings go to scenario-specific folders under `output/playwright/`. All are ignored by Git. Inspect representative captures alongside DOM assertions, especially for Bonk's WebGL stage and fallback. Screenshot cameras show generated test patterns, not participants. These are review artifacts rather than pixel-perfect golden tests. For the UI simplification pass, baseline screenshots and Chrome/WebKit match recordings are retained under `output/playwright/ui-simplification/before/`; matching updated files are under `output/playwright/ready-together/after/`. Review the recorded handoffs for stable faces and captions, readable labels, and immediate action availability. Check grayscale captures and muted judge playback separately from normal audio. Synthetic browser recordings cannot establish physical Android/iPhone behavior or live-provider sound.

## Release limits

Chrome normally uses its built-in synthetic media; the long-utterance scenario uses distinct generated microphone tones in every project. WebKit runs the players in separate processes because its mock devices are shared within a process. Its mock microphone can stop producing audio after reload, so `synthetic-media.ts` supplies a continuous generated tone on the game's unlocked audio clock without opening a native microphone. That tone crosses the normal capture worklet, authenticated socket, private check, and provider adapter. Native microphone permission and acquisition behavior are outside this fixture's coverage; dedicated device-fault tests remain separate. This verifies application flow in WebKit, not native iPhone microphone continuity or audio unlocking.

Live-provider rehearsal and physical two-player matches on desktop Chrome, Android Chrome, and iPhone Safari remain release requirements. Verify real permissions, unplugging, foreground/background interruptions, acoustic echo, perceived speech/effect balance, conversational pacing, and adverse network conditions. Mock provider timing and injected device faults cannot establish those qualities. Current hosting, room durability, and other deployment limitations are documented in the [project README](../../README.md); lifecycle and compatibility rules are in the [protocol guide](../../docs/PROTOCOL.md).
